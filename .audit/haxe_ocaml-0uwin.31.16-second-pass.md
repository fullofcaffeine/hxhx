# Second-pass review: Array slice

## Outcome

The change is safe to close as a one-method, two-call-form hard cut. Final
typed calls to `Array.slice` now carry their exact position, optional end,
generic Array result, source order, and runtime function into OCaml syntax. The
old source-method branch was removed from the late builder.

## Typed call forms

An installed Haxe 4.3.7 typed-AST probe established the relevant forms:

- an omitted end produces one exact `Int` argument;
- explicit `null` produces `Int, Null<Int>`;
- an explicit integer produces `Int, Int`.

The closed model therefore has `SliceDefault` for the omitted end and `Slice`
for a supplied end. The supplied form requires an exact `Int` position and
accepts only `Int` or `Null<Int>` for the end. Both return `Array<T>`.

The probe also showed that macro typing can display a null required position
as `Int`, but the real static compilation rejects that source before the OCaml
backend runs. The vertical test caught this distinction. The invalid case and
an attempted native parameter widening were removed, so the implemented
contract does not claim more than the static target accepts.

Focused corruption changes a supplied end to `Float` and changes the omitted
form's runtime function to the supplied form. Both fail before syntax. Common
validation also checks the root `Array<T>` owner, arity, result, schedule,
runtime requirement, profile, revision, source occurrence, and owner identity.

## Range behavior, copying, and evaluation order

The shared Haxe 4.3.7/generated-OCaml tracer covers positive and negative
positions, omitted and explicit-null ends, negative and oversized ends, empty
results, and unchanged source storage. It records both
`receiver,position` and `receiver,position,end` order.

The omitted form calls `HxArray.slice_default`. That small storage-runtime
wrapper reads the length from the received Array and calls the existing slice
implementation. It does not choose a compiler operation. Its purpose is to
prevent generated syntax from evaluating a side-effecting Haxe receiver twice.

The supplied runtime entry accepts the optional end carrier, checks the Haxe
null sentinel immediately, and continues with one concrete integer. The
position remains an exact OCaml integer. No untyped value enters range or copy
logic.

## Reports, inventory, and claim boundary

The function-plan revision is `v92`, the call-boundary model is `v26`, the
standard Array proof is `v6`, and the lowering schema is 77. The inspection
reader and independent JavaScript consumer validate both slice forms. Six
deterministic reports were regenerated by the repository updater and then
passed an ordinary comparison run.

The private-runtime inventory falls from 338 to 335. The removed entries are
the old `HxArray.slice` call and the two separate `HxArray.length` expressions
used for explicit-null and omitted ends.

No generated OCaml was edited. Runtime source-selection authority and README
Goals did not move. Requirements-only runtime selection remains incomplete,
with 335 private-reference inventory entries still open.

Oracle review was deliberately skipped. The standard Array seam was already
accepted, Haxe 4.3.7 supplied a direct typed and behavioral oracle, and focused,
vertical, inspection, corruption, inventory, and deterministic-report evidence
converged without an unresolved architecture decision.
