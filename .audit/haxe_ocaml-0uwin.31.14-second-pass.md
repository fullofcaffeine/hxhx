# Second-pass review: Array resize and splice

## Outcome

The change is safe to close as a two-operation hard cut. Final typed calls to
`Array.resize` and `Array.splice` now carry their exact operation, types,
result form, evaluation order, and runtime reference into OCaml syntax. The
old source-method cases were removed from the late builder. The separate
`HxArray.resize` call used to implement assignment to `array.length` remains
visible and is not counted as migrated.

## Types and result forms

Selection requires the root Haxe `Array<T>` class and the exact final receiver
type. A user-defined method with the same name cannot enter this path.

`resize` accepts one exact `Int` source argument and returns effect-only
`Void`. `splice` accepts exact `Int` position and length arguments and returns
`Array<T>`. Neither runtime function takes a synthetic trailing `unit`.
Focused corruption checks replace an `Int` with `Float`; the plan rejects the
bad source or formal type before syntax generation. Existing common checks
also cover operation identity, arity, result kind, runtime symbol, revision,
profile, owner, and source occurrence.

## Mutation, range behavior, and evaluation order

The shared Haxe 4.3.7/generated-OCaml tracer grows a nullable integer Array
and observes null-filled new slots, then shrinks the same Array. It splices a
negative start with an oversized length and checks both the returned removed
elements and the remaining mutated Array.

The same tracer records evaluation order. Resize observes `receiver,length`;
splice observes `receiver,position,length`. Each value is produced once, so a
printer cannot duplicate or reorder side effects without failing the real
runtime comparison.

## Runtime authority, reports, and inventory

Both operations reuse the existing `HxArray` runtime implementation. The
Haxe-authored compiler owns when those primitives are called; no handwritten
OCaml compiler semantics or generated-output repair was added.

The function-plan revision is `v90`, the call-boundary model is `v24`, the
standard Array proof is `v4`, and the lowering schema is 75. The public
inspection consumer recognizes both operations, validates every observed
resize contract, and validates any observed splice contract. Its full
corruption/recovery suite passes.

Six deterministic reports were regenerated by the repository updater and
then passed ordinary comparison. Their large textual movement is caused by
stable arrays being sorted by revision-derived identities after the hard-cut
version change; they were not edited by hand.

The private-runtime inventory falls exactly from 343 to 341. The only removed
rows are the late source-method resize and splice cases. One `HxArray.resize`
row remains for Array length assignment, as required.

## Claim boundary

No generated OCaml was edited. Runtime source-selection authority and README
Goals did not move. Requirements-only runtime selection remains incomplete,
with 341 private-reference inventory entries still open.

Oracle review was deliberately skipped. The standard Array seam was already
accepted, Haxe 4.3.7 supplied a direct behavior oracle, and focused, vertical,
inspection, corruption, inventory, and deterministic-report evidence
converged without an unresolved architecture decision.
