# Second-pass review: standard Array `concat` and `copy`

## Outcome

The change is safe to close as a two-operation hard cut. A final typed Haxe
call to the root `Array<T>` declaration now selects `HxArray.concat` or
`HxArray.copy` before OCaml syntax is generated. Other Array methods still use
their existing paths, so this does not complete the requirements-only runtime
selection goal or change public readiness.

## Type and operation identity

Selection requires the root module and class named `Array`, one exact element
type, the expected argument count and types, and an `Array<T>` result. A user
class with a `concat` or `copy` field cannot enter this path. The sealed target
contains the chosen source operation, receiver and argument types, runtime
module and function, profiles, and proof. Defensive copies prevent later
mutation from changing the plan.

The validator rejects a mismatched operation, runtime function, argument list,
source identity, profile, revision, or specialized target from another call
family. Syntax rechecks the target against the final typed occurrence; it does
not choose behavior from the field name.

## Evaluation and runtime ownership

The schedule binds the receiver once, then each source argument once in source
order, then invokes the chosen runtime function. The Array tracer checks that
`concat` evaluates the receiver before its argument and that `copy` returns a
new array rather than an alias.

Each generated `HxArray` reference has one occurrence owned by the exact call
ID, plan revision, expression domain, source span, profile set, and runtime
requirement. Missing, duplicated, stale, foreign-owner, wrong-domain,
wrong-symbol, and wrong-profile occurrences fail focused tests. A plain
unowned `HxArray.concat` reference also fails runtime-use reconciliation.

## Reports, revisions, and deterministic evidence

The first full inspection exposed a useful integration defect: the runtime
requirement was in the request ledger but the lowering report included only
other requirement families. The report writer now derives every call-owned
requirement from the sealed call and compares it with the ledger before
publication. Inspection then validates the Array-specific capability, source,
subject type, feature, module, and profile.

The function-plan revision is `v87`, the call-report model is `v21`, and the
lowering schema is 72. Six checked lowering goldens were regenerated by the
repository's two-run deterministic update mode. Their semantic inventory is
stable except for one new standard Array call and one matching runtime
requirement per fixture; widespread textual movement comes from revision-bound
identities and deterministic re-sorting, not extra feature claims.

## Claim boundary

The independent Haxe run and the generated OCaml build/run both pass. The
private-runtime inventory falls exactly from 353 to 351 because the two late
builder references were removed. No generated OCaml was edited, no handwritten
OCaml semantic owner was added, no README goal moved, and the remaining 351
structured private-runtime references still block the broader hard cut.
